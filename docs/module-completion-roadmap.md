# 系统模块完善清单

本文用于区分“已有入口”“已实现逻辑”和“经过线上验证”，避免把开发中的功能误认为已完成。状态只在有代码或验证证据时更新。

## 交付原则

- [ ] 每个模块先盘点数据流和现有功能，再修复基础问题，最后扩展功能。
- [ ] 所有题目必须区分官方公开题、授权题和平台自编题；不以自编题填充官方真题栏目。
- [ ] 任何依赖 D1 的功能，都要在迁移应用后验证真实远程数据库；GitHub Actions 通过不等于 D1 已迁移或 Worker 已部署。
- [ ] 学习记录的本地缓存、云端记录必须清晰区分；不能显示“已同步”但实际未保存。
- [ ] 每次提交后检查 GitHub Actions；线上功能需另行验证 API 和移动端体验。

## 模块 1：考试题库与练习流程（当前优先）

- [x] 官方题源目录按所选考试切换。
- [x] 练习区增加全部题目、官方过去问、专项练习、授权题目筛选入口。
- [x] /api/questions 支持按来源筛选，并对来源参数使用白名单。
- [x] 官方题目为空时给出明确提示，不把自编题当作真题。
- [ ] 检查题目字段、选项、答案、解析、来源链接和难度等元数据的一致性。
- [ ] 导入经核实可公开使用的 IPA 公开题，并记录年度、出处、科目和适用范围。
- [ ] 补充按知识领域、难度和掌握情况筛选；支持错题、未做题和收藏题。
- [ ] 为答题流程增加自动化测试：正确答案、错误答案、保存失败、空题库、不同考试切换。
- [ ] 评估官方题目与自编练习在模拟考试中的配比和组卷规则。

## 模块 2：错题复习与学习记录

- [ ] 验证 study_attempts、questions 的真实远程 D1 schema 与 API 字段一致。
- [ ] 修复重复错题、重复练习、答题保存失败等边界情况。
- [ ] 显示错误次数、最近作答时间和掌握情况。
- [ ] 复习后根据最新作答更新排序，避免永久只按历史错误次数排列。
- [ ] 明确云端记录与浏览器本地记录的区别，并为断网/保存失败提供恢复提示。

## 模块 3：限时模拟考试

- [ ] 验证倒计时、自动交卷、未答题、手动交卷和切换考试行为。
- [ ] 明确每场考试的题量、时间、计分和及格线配置，避免所有考试共用固定规则。
- [ ] 保存云端考试记录，并提供历史成绩趋势。
- [ ] 补充题目顺序、选项顺序及交卷后统一解析的测试。

## 模块 4：实战演练

- [ ] 检查所有情境的选项、评分规则、最佳选项和解析是否一致。
- [ ] 记录每次练习并展示历史分数与薄弱领域。
- [ ] 按考试、知识领域和难度筛选情境。
- [ ] 明确标注平台自编情境，不冒充官方题目。

## 模块 5：日语与英语学习

- [ ] 盘点课程卡片的数量、分类、例句、读音和来源。
- [ ] 统一本地进度与云端进度的数据模型。
- [ ] 增加收藏、复习队列、已掌握状态和间隔复习。
- [ ] 检查 iPhone Safari 发音兼容性和无可用语音时的降级提示。

## 模块 6：词典与 IT 术语

- [ ] 检查中、日、英词条是否出现空释义、错误读音或不可靠翻译。
- [ ] 统一术语表与在线词典结果的来源标记。
- [ ] 完成生词收藏、取消收藏、跨设备读取和复习流程。
- [ ] 对第三方词典超时、限流和无结果提供稳定的错误状态。

## 模块 7：学习计划、仪表盘与统计

- [ ] 明确每日任务、学习时长、练习次数、正确率各自的数据来源。
- [ ] 把可持久化的学习进度迁移到可靠的云端存储，并保留合理的离线反馈。
- [ ] 修正跨日、时区、清理浏览器数据后统计不一致的问题。
- [ ] 避免把手动录入成绩与真实答题记录混合统计。

## 模块 8：数据库、部署与质量保障

- [ ] 手机无法执行时，继续维护可重复执行、编号连续的 D1 migration；稍后集中应用。
- [ ] 检查全部迁移顺序、唯一键、索引和重复执行行为。
- [ ] GitHub Actions 覆盖类型检查、构建与必要测试。
- [ ] D1 迁移后验证 /api/health、/api/tracks、题库、错题、词典和学习记录 API。
- [ ] 确认 Worker 部署和静态资源版本一致。
- [ ] 评估公开部署的身份认证、数据隔离、写入限流和滥用防护。

## 当前边界

- 目前正式接入的考试题目以 SG 为主，其他考试未接入前不应伪造题目或宣称功能已完成。
- 官方过去问题源目录与“已在站内导入完整题目”是两件不同的事。
- GitHub 提交和 CI 成功不代表远程 D1 migration 已执行，也不代表线上 Worker 已更新。
- 用户当前主要通过 iPhone 操作，实施步骤优先采用可在仓库中准备、以后集中迁移的方式。
