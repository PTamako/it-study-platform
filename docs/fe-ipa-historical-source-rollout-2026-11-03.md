## 生产基线

2026-11-03（JST）在 Cloudflare D1 只读核对：上一轮 PR #106 已部署，FE **320 道**、上一批原创题 `fe-growth1-%` 共 **80 道**、`0119_fe_growth_phase1_original_80.sql` 已迁移。既有 2019 春季旧制度午前问 1～6 共 **6 道**。

* 已有 FE 320 = 原数据库标记 official 116 + licensed 改编 74 + generated 原创 130；
* 本轮新增加 2019 春季午前**问 7～27，共 21 道改编题**：全部逐页核对 PDF，答案逐号核对官方解答；
* 本轮部署后 FE 预期 **341 道**，其中原创 130、官方标记 116、官方题源改编 95。
* IPA 考试制度已变化：**2019 年上午旧制度题**只用于现行科目 A 的知识练习，不得称为现行 CBT A 真实考题，更不得当作现行科目 B。
* 新题标记 `source_type='licensed'`，UI 应显示「真题改编」；绝不将重写的图表/题干标为未改动的 `official`。

## 本批核验依据和操作

- [IPA 2019 年春季 FE 午前原卷](https://www.ipa.go.jp/shiken/mondai-kaiotu/gmcbt8000000ddiw-att/2019h31h_fe_am_qs.pdf)：PDF 原卷页 6～13（纸质页码与 PDF 页码一致），问 7～27。
- [IPA 2019 年春季 FE 午前官方解答](https://www.ipa.go.jp/shiken/mondai-kaiotu/gmcbt8000000ddiw-att/2019h31h_fe_am_ans.pdf)：答案由 IPA 官方公表，包含逐题答案和领域。
- [IPA 使用规则](https://www.ipa.go.jp/shiken/faq.html)：公开问题可依条件用于教育题库，但必须标明年度、期、考试类型、时段、题号以及修改情况。

数据：`scripts/data/fe-ipa-2019-spring-07-27-reviewed.json`，每题含 `original_number`、`pdf_page`、完整源 URL、官方答案 URL、具体改编种类、题干选项、日语和中文解析。

构建：`node scripts/generate_fe_2019_spring_source_review.mjs` 从已提交的数据文件生成 `0120_fe_ipa_2019_spring_morning_07_27.sql`。**本地生成阶段绝不访问 D1 或网络**。Migration 用 `INSERT OR IGNORE` 加入且保持既有学习历史和收藏；未授权修改原题或个人记录。

验证：`scripts/fe-ipa-2019-reviewed.test.mjs` 对 21 个稳定 ID、问号 7～27、官方解答、题源、A/B 分类、避免重复入库、中文解析做断言。计算题还独立验算欧几里得算法比较次数、缓存平均时间、可靠度、音频存储时长。

## 分阶段扩充策略

| 批次 | 重点 | 质量标准 |
| --- | --- | --- |
| 2019 春期剩余 | 午前问 28～80，已收录 1～27 | 逐题核对原卷与官方解答、图表保真 |
| 2019 秋期剩余 | 午前 80 题中尚未入库的题号 | 同原卷，去重、保持分期 |
| 2018 春秋 | 各最多 80 道午前公开题 | 原卷与解答，检查知识是否仍符合现行考试 |
| 2017～2009 | 按每年的春秋官方公开 PDF 分批补齐 | 逐题可追溯的年份、期、问号和图片解释 |
| 更早公开年份／官方免除题 | 按可验证来源择优 | 不预先虚构原题数量，不把样题、改编题算成未修改官方真题 |
| 目标 3,000 | 根据实际官方覆盖与重复去重决定 | **严格区分官方原题、官方题源改编、原创训练** |

到 2019 年为止的 2009～2019 年春秋午前试卷若每场 80 题，则理论上最多有约 1,760 个题位，**并不足以仅靠这段时期达到 3,000**。后续还需要核对更早已公开场次及可用免除试卷，并排除重复/过时问题。过去的 2020～2022 年 CBT 正式题未公开，绝不能臆造年度题号或出处。

## 费用与运行注意

本批 **只需执行一次增量 D1 导入**，对既有学习记录无额外 SQL 扫描；练习 API 保持分页。题库接近 1,000 道之前，必须单独优化 `/api/mock-exam-questions`：该接口目前会把所选考试的所有题行从 D1 读出后才随机组卷，达到 3,000 后会造成不必要的 D1 行读取。只有在安全保持随机组卷、答题隐藏规则与真实题型比例的条件下才能部署优化。
