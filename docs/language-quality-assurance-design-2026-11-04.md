# 词典与语法准确性：可持续审核设计（2026-11-04）

## 范围及真实性边界

审核知学平台已有的 3,010 日语＋3,010 英语静态学习词条、各 5,000 条日英公开句子、24 个自编双语语法主题（48 道练习题），另覆盖上线时在线词典的来源/降级契约。独立于 FE/SG 题库。

**自动测试只能证明结构、已知负例和部分确定性规则正确，不可能证明 16,000 多项内容逐条语义正确。** 跨语言歧义、语境适配、语调和多义词选择必须人工复核。Tatoeba 是社区语料及配对翻译，而不是专业校审译文。严禁将传统/AI 翻译结果直接标记为官方权威释义。

## 审核层级

| 层级 | 数据来源 | 全量自动校验 | 语义复核 |
| --- | --- | --- | --- |
| A. 学习词典 | 固定版本 ECDICT、OpenJLPT、Tomoshi/JMdict；已提交原创词条 | ID/词形/重复、中文词义、来源类型、许可声明、缺少的读音或双语例句统计 | 同形异义、多词性、英语音标与片假名辅助读音的性质、日语读音和音调与具体词义、例句语境 |
| B. 原创语法 | `src/daily-grammar-lessons.ts` | 12＋12 主题、48 题、四个互异选项、合法正确答案、单双语解释、空格数量 | 接续/否定/活用、错误选项是否也能在语境中成立、中文/日文说明是否自然 |
| C. 日英语句 | 指纹版本的 Tatoeba 静态语料 | 5000＋5000、来源链接、译文不空、字符偏移、语法/词汇解释和高亮覆盖、重复和错误 JSON | `の` 名词化与所有格、`から` 动词词干/助词、多义词与语义角色、英文情态/非谓语结构 |
| D. 在线词典 | Jisho、Free Dictionary、精选译文、GAS 翻译、用户主动 Workers AI | 来源标签、响应结构、网络错误/空结果/限流、无可靠元数据时隐藏而非乱填 | 按实际查询词＋语境抽样验证，翻译服务不是词性/重音依据 |

## 本轮实施的第一道质量关卡

1. 构建过程中先由现有脚本生成有许可证的静态词典和句子。
2. `node scripts/audit-language-quality.mjs` **本地读取发布的指纹 JSON**，校验 ID、词源/来源、解释字段、Unicode codepoint 高亮位置、未覆盖解释、重复和 24 个语法主题结构。
3. 无效数据让 CI 失败；缺少可靠读音/双语例句只是统计缺口，不能凭空补造，也不能将其误称为已校对。
4. 按语言×日常/职场四个组，按稳定 ID 抽取至多各 30 条**需复核语义的高风险句子**，生成 `quality-reports/language-quality.json`；报告没有私人学习数据。
5. 发布前后不扫描生产 D1、不会调用 Workers AI、在线翻译或免费配额接口。
6. `scripts/language-quality-audit.test.mjs` 通过故意损坏的高亮、来源、日英解释、Unicode 偏移和语法题目验证质量关卡本身不能被明显错误绕过。

### 继续完成语义验收的流程（不可自动假装完工）

- **P0 高风险优先**：先从报告中的 120 条高风险语料人工核对，再在相应规则上补正例／负例（例如 `分からない` 的 `から`、`食べるのが好き` 的名词化、英语 `used to` 与 `be used to`）。
- **固定金标准集**：每一个人工确认错误，都新增对应双语测试：原文、准确高亮起止位置、期望词义/语法解释、**不该标记的片段**、权威参考和说明。修复后终身做回归。
- **词典字段分级**：`source_verified`（明确源/精确词形与读音）、`reviewed`（人工复核）、`derived`（可追踪规则推导）、`ai_assist`（仅作辅助）和 `unavailable`。尤其日语声调按「表记＋假名读音」核对，拼音与 IPA 不允许 AI 伪造。现阶段源数据并未全部实现字段级标签，不能声称已支持所有分级。
- **抽样策略**：日/英、日常/职场、词性歧义、短句/复句分别抽样，记录通过/需修/无法判断、审核者和日期。统计结果需标注抽样数量；不能将抽样通过率夸大为全部语料正确率。
- **发布标准**：自动结构严重错误为零、已有金标准用例全通过、已确认的 P0 语义错误归零，人工复核队列注明已复核/待复核数量。新的语料版本需要重新抽样。
- **长期维护**：优先修复高复现错误和学习主流程出现的词语歧义；普通使用者可主动报告卡片问题，先去除个人信息，再进入 GitHub Issue 复核。不要上传私密学习笔记和 token。

## 性能与免费额度

静态 JSON 及质量报告在 GitHub Actions 构建机执行。质量检查 **D1 reads=0、D1 writes=0、Workers AI=0**，且不需要新增生产表。线上仍使用原有词典缓存和云端进度 D1 接口，质量审计不应导致用户每次查词都触发新 SQL。

## 交付边界

本轮自动审核系统完成后可以说「离线全量结构质量门槛已启用」；**不能**说「词典、语法解释 100% 语言学准确」或「16,000 项已经人工全部校审」。真实语言准确性是可累积、可追踪的审核记录和精度提升过程。
